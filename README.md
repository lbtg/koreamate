# KoreaMate 韩国地陪预约平台

本分支是基于原项目视觉参考重新编写的可运行开发版本。React 前端、Node.js 服务端及 SQLite 持久数据库共同完成预约业务；不再将账户、地陪、订单存入浏览器 localStorage。浏览器仅保存语言偏好。

## 当前交付范围

- 游客账户、地陪账户和管理员/审核/客服/财务权限；密码 scrypt 哈希、HttpOnly 会话、CSRF 校验、登录失败限流。
- 旅游、商业、医疗、演唱会四类目的，多选按全部满足匹配。
- 城市、韩国日期时间、时长、成人/儿童人数、总预算、中文能力和风格筛选；价格或评价排序。
- 地陪资料、申请与补充资料审核、上架/下架、暂停接单。
- 每周固定开放时间、单日开放、单日关闭；时间冲突及订单间交通缓冲校验。
- 预约申请、地陪接受/拒绝、事务内档期锁定、超时释放、订单历史价格保存。
- 订单消息、站内通知、15秒订单刷新、服务开始/申请结束/游客确认完成。
- 真实已完成订单评价、评价审核与申诉、投诉及证据文字/链接、售后记录。
- 改期方案经游客与地陪同意后生效，生效前重新检查档期；原价格及时长不变。
- 财务收付款台账、部分/全部退款登记、退款后佣金同比例调整、争议订单暂停结算。
- 后台内容、佣金和期限配置、权限管理、操作日志、城市及四类目的统计。

## 必须明确的交付边界

1. **未接通微信/支付宝/银行卡在线支付，也不会自动扣款、退款或转账。** 默认关闭人工收款。仅在平台确认收款主体和线下收款安排后，才可设置 `MANUAL_PAYMENTS=true` 并在后台填写收款说明。财务的“核实到账”“登记退款”“登记结算”用于记录实际完成的外部操作，不会执行资金移动。参考号唯一，收款重放不会重复记账；过期订单不能因迟到款直接变为已确认。
2. **站内通知已实现，短信、邮件、KakaoTalk、微信通知未接入。** 用户需登录查看，订单每15秒刷新。邮箱验证、忘记密码/邮件重置尚未实现，不能据此声称邮箱已验证。
3. **身份、语言和资质由平台线下面试核验。** 软件提供资料审核和审计记录，不声称已接入身份证或职业资格认证机构。头像使用图片网址；没有证件或图片文件上传功能。证据目前为文字/链接。
4. **退款规则由运营人员依已公布的订单约定处理。** 没有自动阶梯退款、拒付、自动对账或税务报表。售后申请本身不表示已取消/已退款。结算后发现退款需求须由财务另行处理，系统禁止直接修改已结算订单的退款台账。
5. **改期已实现；更换地陪、加时补差价尚未实现。** 不支持后台单方替换已约定的地陪或价格。需要这些变更时先协商取消/新建订单。
6. 游客首页、账户和地陪主要资料/档期页面提供中韩切换；订单与管理后台部分业务文案目前为中文，韩文全量本地化需后续补齐。无英文入口。
7. 当前数据库适用于**单个有持久磁盘的 Node 实例**。不能直接部署为 Vercel 静态站或使用无持久磁盘的函数。本次未创建云端生产数据库、未部署公网、未修改原仓库主分支。
8. 医疗等服务类别只是匹配字段，经营主体、实际服务范围和人员资格仍需运营方核实；不是软件完成即可提供所有类型服务。

## 本地启动

要求 Node.js 24 或更新版本、pnpm 11.19.0。

```bash
pnpm install --frozen-lockfile
pnpm run build
pnpm start
```

打开 `http://127.0.0.1:3001`。数据库首次启动时自动创建于 `data/platform.sqlite`。正式数据不随源码交付；初始没有虚构地陪、订单或评价。

开发时两个终端分别运行：

```bash
pnpm run server
pnpm run dev
```

Vite 将 `/api` 转发到 `127.0.0.1:3001`。

### 创建首位管理员

将 `ADMIN_EMAIL`、`ADMIN_PASSWORD`（至少10位）、`ADMIN_NAME` 设置为本机环境变量后执行：

```bash
pnpm run create-admin
```

也可将这些变量放入不提交的 `.env` 并执行：

```bash
node --env-file=.env server/app.mjs --create-admin
node --env-file=.env server/app.mjs
```

不要把管理员密码写入公开仓库或通过聊天发送。创建后移除创建管理员所用的临时环境变量。没有默认管理员密码，注册接口不能创建管理员。

### 首次验收操作

1. 注册一个地陪账户，提交资料及服务目的，设置未来日期的开放时间。
2. 在另一个浏览器用管理员账户登录，在地陪管理中审核通过。
3. 再用游客账户搜索对应日期、时间和目的，进入资料页提交预约。
4. 地陪在自己的工作台看到申请并接受。游客订单变成待付款，时间段锁定。
5. 用第二个游客预约相同时段，验证无法重复确认。
6. 如仅演示预约，到此停止；真实收款未准备好时不要启用人工付款。
7. 已核对付款的订单可执行服务开始、结束、游客确认、评价。财务可在等待期结束且售后解决后登记实际结算。

## 部署给技术人员的说明

- 可使用提供的 Dockerfile 或安装 Node 24 的服务器。必须挂载 `/app/data` 持久卷并配置备份。
- 对外服务置于 HTTPS 反向代理后，将 `NODE_ENV=production`、`APP_ORIGIN=https://你的域名`、`HOST=0.0.0.0` 配置正确；代理应传递真实对外 Host。生产会话 Cookie 带 Secure，不能以纯 HTTP 作为正式入口。
- 设置 `DATABASE_PATH` 到可写的持久路径。多进程/多实例扩容前迁移至共享数据库，并重新验证事务锁、会话及定时任务。
- 提供 `/api/health` 健康检查。每30秒检查待接单和待付款订单超时，每次API请求前也会清理超时状态，重启后能继续恢复。
- 不要复用旧项目的纯静态 `vercel.json` 配置；本分支移除了旧配置。若坚持前端Vercel+独立API，需额外配置API域名、Cookie、代理和跨域策略，不能只上传静态包。
- 生产上线前需真实网络、手机、中文/韩文、运营流程、隐私文本和实际收款的验收；本开发版本不是已经完成第三方认证或安全审计的生产发布。

## 目录

- `src/main.jsx`：游客、地陪及后台页面与接口调用。
- `src/platform.css`：响应式视觉样式，沿用原项目深绿/米白/暖橙方向。
- `server/app.mjs`：HTTP接口、账户、数据库、事务与业务状态规则。
- `tests/platform.test.mjs`：使用隔离临时数据库的集成测试，不操作正式数据。
- `public/`：图标和从原项目参考链接复用的旅行图片。
- `.env.example`、`Dockerfile`：运行配置示例。
