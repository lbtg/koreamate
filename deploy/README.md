# 后端上线与支付接入

## 目前缺少的外部资源

- 一个可运行 Node 24 或 Docker、有持久磁盘的服务器，以及它的 HTTPS 地址。
- 平台自有的 Toss Payments 商户测试密钥；正式收款需已审核的商户与正式密钥。
- 管理员实际使用的邮箱；密码只在服务器环境或终端设置，不通过聊天传递。

现有 Vercel 项目继续承载前端和同源 API 转发。SQLite 文件必须留在持久服务器，不能写到 Vercel 函数临时目录。只允许一个后端实例。微信、支付宝等其他通道未启用；不要把卡支付接入理解为中国支付通道也已开通。

## 持久服务器

1. 拉取 `lbtg/koreamate` 的 `rebuild/full-platform` 分支，复制 `.env.example` 为 `.env`，填入实际配置。
2. `APP_ORIGIN` 填实际对外前端域名；`NODE_ENV=production`；配置随机 `BACKEND_GATEWAY_TOKEN`。`TOSS_SECRET_KEY` 先使用商户自己的测试密钥，`PAYMENTS_ENABLED=true`。
3. 在仓库根目录运行 `docker compose -f deploy/compose.yaml up -d --build`。命名卷 `platform-data` 保留账户、会话、订单及支付流水；不要使用 `down -v` 清除该卷。
4. 用服务器现有 HTTPS 反向代理把后端域名转发到 `127.0.0.1:3001`。不要把未加密的 3001 端口直接暴露公网。访问 `/api/health` 应返回 `{"ok":true}`。
5. 进入服务器终端，安全地临时设置 `ADMIN_EMAIL`、`ADMIN_PASSWORD`、`ADMIN_NAME`，使用相同数据库执行 `node server/app.mjs --create-admin`；Docker 可使用 `docker compose exec -e ... platform ...` 传入本机已有环境变量。创建后移除临时管理员密码变量。
6. 给数据卷配置加密备份和恢复演练。可停服务做一致性快照，或者使用 SQLite 的在线备份工具；不能只复制活跃数据库文件而忽略 WAL。

## Vercel 配置

在现有 `koreamate` 项目的环境变量里添加，且作用于需要启用的 Preview 或 Production 环境：

- `BACKEND_ORIGIN=https://实际后端域名`
- `BACKEND_GATEWAY_TOKEN=与服务器相同的随机值`

然后重新部署同一源码版本。Toss 密钥只在持久后端设置，不能使用 `VITE_` 前缀，也不能写进网页、仓库、日志或 API 响应。API 转发会保留会话 Cookie 与 CSRF 请求头。`APP_ORIGIN` 与用户访问的网址必须一致，否则跨源请求会被拒绝。

未填写 `BACKEND_ORIGIN` 时，服务器接口返回明确的 `BACKEND_NOT_CONFIGURED`；托管版只显示标注的公开示例资料和登录页面，不会建立假账号、假订单或假支付。后端接好后 `/api/session` 来自真实数据库，前端自动停止使用预览数据。连接失败不能退回演示登录。

## 三端入口

- `/`：公开浏览与检索；未登录点击预约会进入游客登录。
- `/login`：游客登录/注册；登录后返回之前选择的地陪或订单。
- `/join`：地陪注册申请；`/guide/login`：地陪登录。
- `/guide`：登录后的地陪工作台；服务器限制地陪身份。
- `/orders`：仅登录用户可查看本人的订单。
- `/admin/login`：独立管理员入口，没有公开注册。
- `/admin`：按管理员、客服、审核、财务权限展示后台并验证每一个接口。

管理员入口不出现在游客导航栏。隐藏入口不是权限防护本身；服务端角色校验、会话、CSRF 和密码校验始终生效。平台负责人创建或授予管理权限。

## Toss Payments 验收与正式启用

1. 在商户后台配置 Webhook：`https://实际前端域名/api/payments/toss/webhook`，事件 `PAYMENT_STATUS_CHANGED`。网关会转发给持久后端。
2. 用平台游客和地陪测试账户完成预约，地陪接受后游客才能打开收银台。
3. 收银台返回 `/payments/success` 仍不代表已付款；点击“确认完成支付”，后端核验订单所有者、金额、币种、付款期限和已保存的支付编号，再请求 Toss 批准。
4. 若请求超时但支付实际已发生，订单保持核对状态并保留档期。后台周期任务或“刷新支付结果”按支付机构查询结果对账，不再次盲目扣款。重复确认和重复通知不会重复记账。
5. 本次 `PAYMENT_STATUS_CHANGED` 接口不假设不存在的通用签名字段。通知只作为查询提示：使用平台自有订单号和服务端密钥向 Toss 重新查询，不信任通知里的金额和成功状态。匿名通知不能发起批准扣款。
6. 财务“发起原路退款”会调用真实退款 API；金额、权限、可退余额、已结算状态都由服务器检查。退款请求先落库，再带唯一幂等键调用；异常请求保留待核对状态并阻止结算。
7. 人工收付款登记不能覆盖在线支付订单。地陪结算仍是财务实际打款后登记，尚未接入自动分账或向地陪银行账户打款。
8. 用自己的商户测试环境验证支付成功、失败、取消、重复回调、部分及全额退款；检查财务流水后再设置正式密钥。测试接口覆盖不等于支付机构联调验收。

Toss 请求的幂等键有效期有限：自动退款重试在 14 天后停止发起资金操作，转人工核对。长期无法核实的支付保留档期并提醒财务，不以猜测结果释放。异常到账不会自动恢复被关闭的预约，需要财务核对退款。

官方接口依据：
- https://docs.tosspayments.com/en/api-guide
- https://docs.tosspayments.com/en/webhooks
- https://docs.tosspayments.com/reference

## 预约双方的专属聊天

- 地陪接受预约时，在同一个数据库事务中创建该订单唯一的会话。双方从订单页“打开聊天”或顶部“消息”进入 `/messages/会话编号`。
- 未登录、其他游客、其他地陪、管理员和财务账户都不能冒用对方进入会话或发送消息。服务器逐请求校验订单双方身份。
- 消息保存到持久数据库，支持会话列表、未读数、已读位置、历史分页、发送失败后以原消息编号重试；重复请求不会生成重复消息。
- 当前使用可见页面每5秒同步，后台页面暂停轮询，恢复可见后重连。不是秒级 WebSocket 推送，不提供在线状态、图片/语音或系统推送；关闭网站后不会收到短信或微信提醒。
- 待付款及后续有效订单可以聊天；取消、过期、拒绝后只读保存。相同双方的新预约生成新会话。
- 客服/管理员只有在存在待处理售后的订单中，填写原因后才能调阅最近500条沟通，并写入审计记录。财务没有聊天读取权限，客服不能冒充双方发消息。
